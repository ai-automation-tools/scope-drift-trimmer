ai-automation-tools · access review for non-human identities

Granted vs. used, for every bot and service account

This page runs the sdt engine on a fictional estate: 8 identities, 16 grants across Entra ID, AWS, GitHub, Okta and Slack. Each grant sits next to the platform's own record of its use, and nothing is called unused unless that record exists. Every fix is a draft you review and run yourself.

Most severe first

Severity is written out, not just coloured. Open a row's evidence to see the data, the window and the source file it rests on.

Identities

Every grant, passing ones too

usageKnown: true means the platform records whether this grant (or the identity) was used over the window. usageKnown: false grants are never judged used or unused.

How it grades

Evidence first

Four rules: dormant-privileged-identity, unused-grant, narrower-permission-available and usage-not-observable. AWS iam:PassRole, data-plane actions and GitHub App permissions leave no per-grant usage record, so they only ever appear as "not observable". Your own file is read with the browser's file API and analyzed on this page; it is never uploaded. The command-line tool runs the same code: sdt analyze inventory.json --out out.json.

Sample data is fictional: example.com owners, AWS documentation account 123456789012, made-up tenant and app ids. ai-automation-tools.dev
