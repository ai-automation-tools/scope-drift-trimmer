The Scope-Drift-Trimmer roadmap routine works this file top to bottom, one item per run, as
`roadmap/auto-` PRs: it takes the first open item that isn't `🔒 Needs owner` (or up to six
`small` ones), builds it and ticks it. **Every item above
`## After public release` is a release gate.** Scope Drift Trimmer goes public when all of them
are ticked and Mike says so. Ticking an item adds its line to the [changelog](CHANGELOG.md) and
updates any doc it made stale, in the same commit.

Markers: `- [ ]` open, `- [-]` claimed by a run in progress, `- [x]` done, `- [!]` blocked
(the reason follows on the line). `small` marks docs or config a run can batch, up to six
per PR (untagged means a feature, one per run); `🔒 Needs owner` marks one only Mike can do.

The slices come from [product/build-plan.md](product/build-plan.md), which marks Slices 0 to 3
as the MVP. Slice 0's scaffold and CI shipped with the repo, so what's left of it is the gate
check. Slices 1 to 3 are the three features above the line, and deploying Slice 2's page is the
live-demo item in the release phase. Every slice is tested against fictional fixture exports
this repo owns; no item needs a real tenant, a credential or network access.

## ⚖️ Slice 1: Engine and rules

- [x] **Evidence-graded engine on the inventory format** (MVP feature 1). Vendor the Agent Security Suite's agent inventory schema v0.1 to `schemas/agent-inventory.schema.json` and validate every read and write against it; an invalid document exits non-zero with the schema path of the first error and writes nothing. The `Adapter` interface (`parse(files) -> identities[]`) with the inventory-passthrough adapter and a shared contract test (schema-valid output, stable ids across two runs, nothing outside the schema except under `x`). The four rules, `dormant-privileged-identity`, `unused-grant` (suppressed when the identity already has a dormant finding), `narrower-permission-available` (a versioned data table seeded with GitHub repository administration → `repository_creation`) and `usage-not-observable`, each with a firing and a non-firing fixture, plus one fixture proving no `usageKnown: false` grant is ever called unused. Draft remediation templates for Entra, AWS, GitHub and Okta, every one starting `DRAFT. A human reviews and runs this. Validate against the target environment first.`; verify the Okta scope-grant revoke endpoint from Okta's docs before writing its template and cite it in a code comment. `sdt analyze <inventory.json> --out <file>` with a text summary and `--fail-on <severity>`. Another producer's sample round-trips with its identities, findings and `x` keys unchanged. A test runs the CLI with outbound sockets stubbed to throw. Empty inventory, malformed JSON, unknown schema version and an identity with no grants each have a fixture. — done 2026-11-05: `src/schema.ts` (dependency-free validator for the vendored schema), `src/inventory.ts` (Adapter + passthrough), `src/rules.ts`, `src/remediation.ts`, `src/engine.ts`, `src/cli.ts`; 33 tests in `tests/` over fixtures in `tests/fixtures/`; Okta revoke verified as `DELETE /api/v1/apps/{appId}/grants/{grantId}`

## 📥 Slice 3: AWS and Entra import

- [x] **AWS and Entra import adapters** (MVP feature 3). AWS: reads Access Analyzer unused-access findings JSON and `GetServiceLastAccessedDetails` output; unused actions become `usageKnown: true` grants, `iam:PassRole` and data-plane actions become `usageKnown: false`, `observationDays` equals the analyzer's window, and the analyzer's own recommended policy is used as the draft when present. Entra: reads a Graph export of service principals, `appRoleAssignments`, `oauth2PermissionGrants` and `servicePrincipalSignInActivity`; `lastUsedAt` is the latest sign-in timestamp, grants are `usageKnown: true` only when the app never signed in inside the window, otherwise `usageKnown: false` with the reason in evidence. Both pass the adapter contract test against committed fictional fixtures built from the documented response shapes, and drop any field that looks like a secret value. `sdt analyze` accepts export files as well as an inventory. Check from Microsoft's docs whether `servicePrincipalSignInActivity` needs Entra ID P1/P2 and say so in the README; if it has left beta or been removed, add a `🔒 Needs owner` item under this one (the memo's Entra falsifier). A rule catalog at `docs/rules.md`, linked from `docs/README.md`. — done 2026-11-10: `src/aws.ts` and `src/entra.ts` behind the `Adapter` interface, routed by file shape in `src/import.ts`; `sdt analyze` takes export files and folders; fictional fixtures in `tests/fixtures/aws/` and `tests/fixtures/entra/`, 14 tests in `tests/import.test.ts`, a CLI test and the contract test; Microsoft Learn says the sign-in report needs Entra ID P1/P2 and is still beta (not removed), so no falsifier item; export commands in the README, catalog in `docs/rules.md`
